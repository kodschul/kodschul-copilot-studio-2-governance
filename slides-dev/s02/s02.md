---
layout: theory
title: 'Lab 3.1 · Gerätekonformität'
---

<div class="qa-block"><p class="qa-q">Was macht ein Gerät konform?</p><ul class="qa-a"><li>Die IT-Abteilung legt in Intune Konformitätsrichtlinien fest (z. B. Verschlüsselung aktiv, aktuelles Betriebssystem, kein Jailbreak/Root). <em>Quelle: Microsoft Learn Intune-Konformitätsrichtlinien.</em></li></ul></div>

<div class="qa-block"><p class="qa-q">Warum Voraussetzung statt Empfehlung im Zero-Trust-Modell?</p><ul class="qa-a"><li>Zero Trust geht davon aus, dass kein Zugriff automatisch vertrauenswürdig ist — Gerätekonformität wird aktiv geprüft, bevor Zugriff gewährt wird. <em>Quelle: Microsoft Learn Zero-Trust-Prinzipien.</em></li></ul></div>

<div class="qa-block"><p class="qa-q">Zusammenhang mit Conditional Access aus Lab 2.1?</p><ul class="qa-a"><li>Der Gerätestatus ist eines der vier Signale, die eine Conditional-Access-Richtlinie auswertet — Intune liefert das Signal, Conditional Access setzt es in eine Zugriffsentscheidung um. <em>Quelle: Microsoft Learn Intune + Conditional-Access-Integration.</em></li></ul></div>

<p class="text-sm opacity-70 mt-2"><strong>Grenze:</strong> detaillierte Konformitätsprofile für einzelne Betriebssysteme → Parkplatz bzw. internes IT-Team.</p>

<p class="text-sm opacity-70 mt-4">Intune prüft Gerät gegen Konformitätsrichtlinie → Ergebnis als Signal → Conditional Access (Lab 2.1) nutzt es für die Zugriffsentscheidung.</p>

---
layout: theory
title: 'Lab 3.2 · App Protection Policies'
---

<div class="qa-block"><p class="qa-q">Wann App-Schutz statt Geräteschutz?</p><ul class="qa-a"><li>Wenn das Gerät nicht vollständig vom Unternehmen verwaltet wird (BYOD) — dort lässt sich nur die Unternehmens-App absichern, nicht das gesamte Gerät. <em>Quelle: Microsoft Learn Intune App Protection Policies.</em></li></ul></div>

<div class="qa-block"><p class="qa-q">Was passiert bei Austritt?</p><ul class="qa-a"><li>Die Unternehmensdaten innerhalb der geschützten App können selektiv gelöscht werden ("Selective Wipe"), ohne private Daten zu berühren. <em>Quelle: Microsoft Learn Selective-Wipe-Dokumentation.</em></li></ul></div>

<p class="text-sm opacity-70 mt-2"><strong>Grenze:</strong> Feinsteuerung einzelner App-Protection-Einstellungen je Plattform → Parkplatz bzw. internes IT-Team.</p>

---
layout: theory
title: 'Lab 3.3 · Endgerät bewerten'
---

<div class="qa-block"><p class="qa-q">Welche Signale zuerst?</p><ul class="qa-a"><li>Konformitätsstatus (Intune), Anmelderisiko (Entra ID) und Zugriff auf klassifizierte Inhalte (Purview) — dieselben Signalquellen wie in der Plattform-Landkarte aus Modul 2. <em>Quelle: Microsoft Learn Intune + Security-Signal-Priorisierung.</em></li></ul></div>

<div class="qa-block"><p class="qa-q">Sperren vs. einschränken?</p><ul class="qa-a"><li>Sperren bei hohem Risiko mit potenziellem Datenabfluss; Einschränken (z. B. nur Web-Zugriff) bei moderatem Risiko mit weiterer Arbeitsfähigkeit. <em>Quelle: Microsoft Learn Conditional-Access-Reaktionsoptionen.</em></li></ul></div>

<div class="qa-block"><p class="qa-q">Was liefert Security Copilot zusätzlich?</p><ul class="qa-a"><li>Eine zusammengeführte Ersteinschätzung über mehrere Signalquellen gleichzeitig — schnellere Orientierung, keine automatische Entscheidung.</li></ul></div>

<p class="text-sm opacity-70 mt-2"><strong>Grenze:</strong> automatisierte Sofortmaßnahmen ohne menschliche Freigabe → Parkplatz bzw. internes Security-Team.</p>

<div class="qa-block"><p class="qa-q">Was übernimmt Copilot, was nicht?</p><ul class="qa-a"><li>Copilot kann aus einer strukturierten Datengrundlage einen zusammenfassenden Text entwerfen, aber es erhebt oder verifiziert die Zahlen nicht selbst. <em>Quelle: Microsoft Learn Copilot-für-Reporting-Dokumentation.</em></li></ul></div>

<div class="qa-block"><p class="qa-q">Warum jede Zahl gegen die Quelle prüfen?</p><ul class="qa-a"><li>Copilot kann Zahlen falsch übernehmen, runden oder anders interpretieren — dasselbe Halluzinationsrisiko wie bei allen KI-Ausgaben.</li></ul></div>
